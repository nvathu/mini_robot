# Robot Camera Projection Test

Script to test the 3D→2D projection (`project_to_pixel`) used in the RGB + MoCap room point-cloud pipeline.

## Context

During review, `project_to_pixel()` was found to use the wrong sign compared to the standard pinhole formula (`u = fx*Xc/Zc + cx`), and was inconsistent with the inverse direction (`unproject`) used throughout the point-cloud pipeline. It has been fixed to match the standard formula. `test.py` is a visual sanity check on real images: it projects the known MoCap position of robot S1 onto the image and checks whether the green dot lands on the real robot.

## How to run

```bash
pip install -r requirements.txt
python calibration.py --body-offset 0.07 --source resnet ( to  fit AFFINE d_true = a * d_pred + b)
python point_could_each.py ( to generate the point cloud) 
python visual_each.py (to visual the point cloud)
```

Output is saved in `test_projection_output/`, one image per sample with a green dot at the predicted position of robot S1.

## Interpreting the results
After tyoe  python visual_each.py , a  window show pointcloud will appear an
Keyboard controls:
  Right Arrow : Next point cloud
  Left Arrow  : Previous point cloud
  Esc         : Exit
  Mouse       : Rotate, zoom, and move the view
  M           : toggle fused model <-> per-frame
  C / W       : camera frame / world frame   (1 : front view, 2 : top-down, 3 : oblique)
  +/- (Open3D built-in) : point size

Coordinate frame:
  Markers: S1 = green, S2 = red (MoCap, offline reference only).
  blue line: path of the robot
  Camera: camera frame -> camera = origin of the RGB axes (looks along -Z of the screen = into the scene);
  world frame / fused model -> blue frustum = camera pose (apex = camera, opens toward the viewing direction)
